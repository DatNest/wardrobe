# Wardrobe — исправление сетевой ошибки `Failed to fetch` (v5)

## Самое важное

**Сначала сохрани резервный JSON с телефона.** Если он уже скачан, не удаляй его. Не очищай браузер, не удаляй данные сайта и не меняй `wardrobe.json` в GitHub на пустой файл.

В этом архиве **намеренно нет** `wardrobe.json` и `images/`: эти файлы могут содержать единственную опубликованную копию вещей и фотографий.

## Установка

1. В своём GitHub-репозитории сайта замени **только `index.html`** на файл из архива.
2. При желании обнови README.md и robots.txt. **Не перезаписывай `wardrobe.json` и `images/`.**
3. Вначале открой сайт на **телефоне**, где заполнен каталог, и проверь, что вещи остались.
4. Настройки GitHub (шестерёнка) → **«Проверить подключение»**. Если всё хорошо, сохранение с телефона начнётся автоматически; стрелка вверх запускает его вручную.
5. Только после подтверждённого сохранения открой сайт на ПК: он прочитает уже обновлённый каталог.

**Не импортируй резервную копию повторно, если вещи уже видны.** Импорт предназначен для восстановления и может сохранять конфликтующие записи как отдельные копии.

## Что изменилось

- Обычное чтение **публичного** GitHub-репозитория происходит без GitHub-токена: меньше лишних CORS/preflight-запросов. Токен продолжает использоваться для записи.
- Вместо сырого `Failed to fetch` отображается, при какой операции не получилось связаться с GitHub, и что именно можно проверить.
- Кнопка **«Проверить подключение»** дополнительно проверяет публичную доступность `api.github.com`, если запрос к каталогу не прошёл.
- Если GitHub API недоступен, но открывается опубликованный `wardrobe.json` по адресу самого сайта на GitHub Pages, программа **только добавляет недостающие записи из публичной версии**. Она не удаляет локальные записи и не объявляет такую загрузку успешной синхронизацией. Публикация GitHub Pages может отставать от состояния репозитория.
- У фоновой синхронизации остаётся интервал **12 минут**, проверка при возвращении на вкладку, запись после правок, одна активная операция одновременно. Нет бесконечных параллельных запросов.
- Ошибки сети **не** очищают каталог и **не** показывают ложное «всё синхронизировано».

## Если опять возникает `Failed to fetch`

Открой **https://api.github.com/zen** прямо в том браузере, где проблема.

- Если страница **не открывается**, у этого браузера нет доступа к GitHub API. Проверь интернет, VPN, фильтры DNS, блокировщик рекламы и попробуй другой браузер или сеть. Это не чинится одним изменением `index.html`.
- Если она открывается, но **отправка с токеном** не работает, открой настройки Wardrobe → «Проверить подключение» и посмотри полный диагностический текст. Это может быть блокировка авторизованных запросов, расширение браузера либо политика сети.
- Если ответ `401`, `403` или `404` — это отдельная ошибка GitHub API. Проверь адрес репозитория, ветку и токен **Contents → Read and write**; но токен никому не присылай.

GitHub Pages — статический сайт. Сам `index.html` не может гарантированно обойти блокировки GitHub API при отправке данных. В таком случае временно сохраняй резервный JSON и не стирай исходный каталог телефона.

## Данные и приватность

- Телефонный JSON остаётся твоей резервной копией.
- Токен хранится только в браузере на том устройстве, где введён, и **не** входит в JSON-резервную копию.
- Публичный репозиторий означает, что `wardrobe.json` и опубликованные фотографии доступны тому, у кого есть ссылка. Не публикуй там чувствительные сведения.
- Если не получается синхронизировать, можно сообщить **адрес публичного сайта или репозитория** и текст диагностики, но **не** GitHub-токен.
